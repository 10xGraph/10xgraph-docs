**Prompt injection is text that makes a language model follow an attacker's instructions in place of the developer's.** The model reads your system prompt and the user's message as one stream of text. If the user's text says "ignore all previous instructions", the model may comply. OWASP lists it as LLM01 in its Top 10 for LLM applications.

## What are the two forms?

- **Direct.** The attacker is the user. They type instructions that try to override your prompt, change the agent's role, or make it reveal its system prompt.
- **Indirect.** The instructions sit in content the agent reads: a web page a tool fetches, a document in a retrieval index, an email, a tool result. The user may never see them.

Indirect injection is the harder one, because the agent trusts the tool it called.

## Why is it dangerous for agents?

A chatbot that is tricked says something wrong. An agent that is tricked can act: send a message, issue a refund, delete a record. The damage depends on what tools the agent can call and with whose permissions.

## What defends against it?

No single control stops it. Combine layers:

1. **Input validation.** Reject messages with known override patterns, role-change phrases, delimiter tricks and encoded payloads before the model sees them.
2. **Narrow tools.** Give the agent only the tools it needs, and check scopes inside tools that change data.
3. **Replay-safe, idempotent tools.** So a tool called twice, or called in error, does not do the damage twice.
4. **Human approval.** Pause before a risky tool runs.
5. **Server-side identity.** Never take the user's identity from model output or message text. Identity must come from the authenticated request.

## What does 10xGraph provide?

`PromptInjectionValidator` checks messages for excessive length, instruction-override patterns, role manipulation, system-prompt leakage requests, delimiter confusion and encoding tricks. It raises a `ValidationError` before the model is called when `strict_mode` is on. Register it with `register_default_validators`.

The limits are stated plainly: validators are heuristic, so a rephrased attack can pass, and they do not cover indirect injection. They also do not replace authorization. See [Validate input and guard prompts](/docs/guides/protect-against-prompt-injection) and [Security and validators](/docs/concepts/security-and-validators).
