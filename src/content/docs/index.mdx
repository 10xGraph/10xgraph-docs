faq:
  - q: "Is 10xGraph production-ready?"
    a: "The production layer ships today in the `10xgraph-api` package: an API server with JWT or custom auth, owner-only thread access, rate limits, durable checkpointing with Postgres or SQLite, replay-safe tools, and Docker and Kubernetes files from `10xgraph build`. Some of it you must configure: with `auth` unset the server runs open, even with `MODE=production`. From 1.0 the public API is stable under a deprecation policy (breaking changes only in a major release, after at least one minor of deprecation), and 1.0 is a release candidate until the final ships. Pin exact versions and read the changelog before each upgrade. See Production readiness for what is covered and what is not."
  - q: "Do I need LangChain to use 10xGraph?"
    a: "No. 10xGraph has no LangChain dependency. You build graphs with its own StateGraph and Agent classes and call model providers through its own interface."
  - q: "Which models does 10xGraph support?"
    a: "OpenAI, Google Gemini (including Vertex AI) and Anthropic (direct API, Vertex AI and Amazon Bedrock), plus any OpenAI-compatible endpoint such as Ollama or vLLM. Swapping the model string does not change your graph or tools."
  - q: "Can I self-host 10xGraph?"

You build the agent. Served with `10xgraph-api`, it gets authentication, per-user thread isolation, rate limits, durable state, replay-safe tools and Docker and Kubernetes deploy files, without you writing that layer. 10xGraph (formerly Agentflow) is an open-source Python framework for production multi-agent AI.

<Callout type="note" title="Why 10xGraph: you build the agent, we ship the server">
Most frameworks stop at the graph. 10xGraph gives you the production API server too: secure by default, horizontally scalable and ready to deploy, with every part (authentication, authorization, rate limits, storage) replaceable. [See what the server does for you and how to customize it](/docs/get-started/why-10xgraph).
</Callout>

## The three packages

They work together or standalone.

- **Core library** (`10xgraph`, import `tenxgraph`): `StateGraph`, `ReactAgent` and other prebuilt agents, tools as plain Python functions, state, checkpointing to memory, SQLite or Postgres, tool replay on failure, streaming, MCP and dependency injection. Add one provider extra such as `10xgraph[openai]`. You can run an agent from Python with no server.
- **API server and CLI** (`10xgraph-api`, import `tenxgraph_api`, command `10xgraph`): you point `10xgraph.json` at your compiled graph, and it serves REST and WebSocket endpoints with auth, authorization, rate limits, threads, memory, files and observability. `10xgraph dev` runs it locally; production runs Gunicorn in the image from `10xgraph build`.
- **TypeScript client** (`10xgraph-client`): a typed SDK for Node.js and browsers covering invoke, stream, threads, memory and files. Plain HTTP or curl works too.

## What the docs cover

Navigate by the question you want to answer.

**[Get Started](/docs/get-started).** Installation, your first agent, the production template, and how to migrate from Agentflow. Read this first.

**[Concepts](/docs/concepts).** The mental model: graphs, state, messages, agents, tools, threads, checkpointers, memory, context, interrupts, streaming, serving and events. Understand how 10xGraph works.

**[Production](/docs/production).** What the server gives you and how it works: the security model, architecture, scaling and reliability, and what 10xGraph does not protect. Read this to decide whether to trust it.

**[Build Agents](/docs/guides).** How-to guides for building: custom graphs, prebuilt agents, tools, MCP, state, dependency injection, memory, context, multi-agent orchestration, streaming, media, authentication, interrupts, testing and observability. Each guide is a complete recipe with code.

**[API Server](/docs/server).** Run and configure the server: the CLI, configuration file, authentication, authorization, rate limiting, REST and WebSocket endpoints, files and multimodal, observability, deployment to Docker and Kubernetes, and production checklist. Use this when you need to serve your agent over HTTP.

**[TypeScript Client](/docs/client).** Call the server from a Node.js backend or browser frontend: create a client, invoke the graph, stream responses, manage threads, upload files, retrieve memory. Works with Next.js, React and plain TypeScript.

**[Testing and Evaluation](/docs/testing).** Unit test with mocked models, run eval sets against your agent, define criteria, simulate users, and generate reports. Verify your agent works before it ships.

**[Integrations](/docs/integrations).** Connect to models (OpenAI, Google, Anthropic), frameworks (FastAPI, Next.js, CopilotKit), storage (Postgres, Redis), and coding assistants. Each integration shows how and when to use it.

**[Examples](/docs/examples).** Runnable code you can clone and modify: simple agents, custom state, tools, streaming, MCP, multi-agent, memory, media, production patterns. Build on these rather than from scratch.

**[Reference](/docs/reference).** Exact signatures, parameters and return types for the Python library, REST API, CLI, configuration and TypeScript client. Use this when you need to check an option or understand an error.

**[Troubleshooting](/docs/troubleshooting).** Symptoms, causes and fixes. Common errors with solutions. Error code reference. Start here if something is not working.

**[Glossary](/docs/glossary).** Plain definitions of AI agent concepts: what is a ReAct agent, state graph, durable execution, idempotent tools, interrupts.

**[Compare](/docs/compare).** 10xGraph vs LangGraph, CrewAI, AutoGen, LlamaIndex and Google ADK. Honest side-by-sides, including where other frameworks are stronger.

**[Project](/docs/project).** Roadmap, security policy, upgrade guides, support and how to contribute.

<Callout type="note" title="Formerly Agentflow">
10xGraph was published as Agentflow until 2026. The Python packages are now imported as `tenxgraph` (core library) and `tenxgraph_api` (server), as in `from tenxgraph import StateGraph`. The old `agentflow` and `agentflow_cli` imports stay available as deprecated aliases until 2.0. See [Coming from Agentflow](/docs/get-started/coming-from-agentflow) for the full migration path.
</Callout>
