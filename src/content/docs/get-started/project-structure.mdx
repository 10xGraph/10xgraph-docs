`10xgraph init --mode full` scaffolds a deployable agent project: a `graph/` package with a state class, a weather tool, a prompt-injection validator and lifecycle hooks, plus `tests/`, `evals/`, ruff and pre-commit setup, an env template and a generated `10xgraph.json`. This page walks through every file and the config keys init writes.

## Generate the project

Run init with the Full setup. The interactive command asks only the agent name, setup and AI provider, then writes the recommended setup. The command below writes a JWT-protected project with in-memory storage and a memory cache store, rate limiting and token revocation, and skips all prompts. Add `--storage postgres` for a Redis cache store.

```bash
# Scaffold a production project in the current directory without prompts
10xgraph init --mode full --name MyAgent --yes
```

Without `--yes` or `--non-interactive`, init asks the three questions interactively. The setup choice defaults to Quick, and `--yes` without `--mode` also gives you Quick.

| Option | Values | Default | Purpose |
|---|---|---|---|
| `--mode` | `quick`, `full` | `quick` | Which project to scaffold. Quick is a minimal graph with no auth. `--template quick-start\|production` is an alias. |
| `--auth` | `none`, `jwt`, `custom` | `jwt` | Authentication scheme. Needs `--mode full`. |
| `--storage` | `memory`, `sqlite`, `postgres`, `postgres-memory` | `memory` | Checkpointer and store preset. Needs `--mode full`. |
| `--cache-store` | `memory`, `redis` | Follows `--storage`: `memory` for `memory` and `sqlite`, `redis` for `postgres` and `postgres-memory`; `redis` with a worker | Cache store type. Needs `--mode full`. |
| `--rate-limit` / `--no-rate-limit` | flag | on | Adds or leaves out `cache_store.rate_limit`. Needs `--mode full`. |
| `--token-revocation` / `--no-token-revocation` | flag | on with auth | Adds or leaves out `cache_store.token_revocation`. Ignored with `--auth none`. |
| `--websocket` / `--no-websocket` | flag | off | Writes `websocket.enabled`. |
| `--name` | text | Directory name, or `MyAgent` when the path is `.` | Agent name, used for the package name in `pyproject.toml` and `APP_NAME` in `.env.example`. |
| `--path`, `-p` | directory | `.` | Where to scaffold the project. |
| `--yes`, `-y` | flag | off | Accept defaults and do not prompt. |
| `--non-interactive` | flag | off | Fail instead of prompting. Use it in CI. |
| `--dry-run` | flag | off | List the files that would be created without writing anything. |
| `--force`, `-f` | flag | off | Overwrite files that already exist. |

Init never overwrites silently. If any target file exists, it stops with `File already exists ... Use --force to overwrite.` Run `--dry-run` first when you scaffold into a non-empty directory.

## See what init creates

Init writes the tree below. The `auth/` folder exists only with `--auth custom`; with `none` or `jwt` it is skipped.

<FileTree>

- 10xgraph.json Config the API server and CLI read on every run
- AGENTS.md Points coding agents to the 10xGraph docs
- .gitignore Keeps .env and credentials out of git
- .env.example Environment template; copy to .env and add your API key
- .python-version Python version pin (3.13 in the template)
- .pre-commit-config.yaml Git hooks for formatting, linting and security checks
- pyproject.toml Dependencies, ruff, pytest and coverage settings
- graph/ Your agent package
  - agent.py Builds the ReactAgent and exports the compiled graph as `app`
  - state.py Custom AgentState subclass
  - tools/ Tool functions
    - weather_tool.py Example tool with retries and progress events
  - validators/ Input validation and lifecycle hooks
    - manager.py Builds the CallbackManager and registers everything
    - validators.py PromptInjectionValidator configuration
    - lifecyle.py Lifecycle hooks (the filename spelling is the template's)
- auth/ Only with `--auth custom`
  - agent_auth.py BaseAuth subclass with an unimplemented authenticate method
- worker/ Only with a background worker (`--worker`)
  - tasks.py Example TaskIQ background tasks
- evals/ Evaluation files, unless turned off
  - weather_agents_eval.py Eval set built with EvalSetBuilder
  - user_simulator_eval.py Simulated-user scenarios
- tests/ Pytest suite, unless turned off
  - conftest.py Sets a dummy GEMINI_API_KEY for tests
  - test_graph_nodes.py Checks on the agent configuration and routing
  - test_catalog_tools.py Tests for get_weather
  - test_agent_eval.py Tests for the eval set and report writing

</FileTree>

The Quick setup is smaller: `graph/__init__.py` and `graph/agent.py` (a single-file agent with its tool), `.env.example`, `.gitignore`, `AGENTS.md`, `requirements.txt` and `10xgraph.json`. `requirements.txt` lists `10xgraph[<provider extra>]` and `10xgraph-api`, and `10xgraph build` installs from it.

## How the pieces connect

The API server reads `10xgraph.json`, imports `graph.agent:app`, and runs it. `agent.py` pulls in the state class, the tool and the callback manager, so each file below plugs into that one graph.

| Piece | Role |
|---|---|
| `10xgraph.json` | Points the server at `app`, and at the auth, thread-name and DI hooks. |
| `graph/state.py` | Defines the working state the graph reads and writes, saved by the checkpointer. |
| `graph/tools/` | Functions the model can call. |
| `graph/validators/` | Checks input before the graph runs and reacts to graph events. |
| `tests/` | Unit tests, run with `10xgraph test`. |
| `evals/` | Behavior evaluations, run with `10xgraph eval`. |

## Read the generated files

### graph/agent.py: the entry point

This file builds a `ReactAgent` with `WeatherState`, the `get_weather` tool, a `MessageContextManager` (last 20 messages, tool messages removed) and `trim_context=True`, compiles it with the checkpointer for your storage choice and the callback manager, and exports the result as `app`. It also defines `container`, the InjectQ container that `"injectq": "graph.agent:container"` points at. `{user_location}` in the system prompt is filled from the `user_location` field of `WeatherState`.

### graph/state.py: custom state

The state class extends `AgentState` with your own fields. Fields you add persist with each checkpoint and are available to prompts and tools.

```python title="graph/state.py"
from tenxgraph.core import AgentState


class WeatherState(AgentState):
    user_location: str = ""
```

### graph/tools/weather_tool.py: an example tool

The tool takes the model's `location` argument plus three optional injected parameters. `tool_call_id`, `state` and `emit` are supplied by the runtime and are not shown to the model.

`call_weather_api` is a stub that fails at random, so the retry loop is easy to see. Replace it with a real API call. Add your own tools as new files in `graph/tools/` and list them in `tools=[...]`. See [Use the @tool decorator](/docs/guides/use-tool-decorator) for how the schema is built.

### graph/validators: input checks and lifecycle hooks

The `validators/` package holds a prompt-injection guard, a lifecycle hook class, and a manager that registers both. `manager.py` creates the `callback_manager` that `agent.py` passes to `compile()`.

`validators.py` creates a `PromptInjectionValidator(strict_mode=True, max_length=10000)` with a short `suspicious_keywords` list.

Tune `suspicious_keywords` to your domain. See [Protect against prompt injection](/docs/guides/protect-against-prompt-injection).

`lifecyle.py` defines `AgentLifecycleHook(GraphLifecycleHook[WeatherState])` with stub implementations of seven async hooks, each returning `None` to keep state unchanged (`on_graph_start` returns the state it received).

Override only the hooks you need. The full contract is in [Use callbacks](/docs/guides/use-callbacks).

### Thread names

Full writes `"thread_name_generator": "first_message"` in `10xgraph.json`, which names a thread from the user's first message. Quick-start leaves the key unset, which means none: threads are saved without a name.

The other choices are `random` for a random two-word name, or a `module:attr` path to your own `ThreadNameGenerator` subclass. See [Generate readable thread names](/docs/server/configure#generate-readable-thread-names) for a custom class.

### auth/agent_auth.py: custom authentication

With `--auth custom`, init scaffolds a `BaseAuth` subclass that rejects every request with 401 until you implement `authenticate`. Its constructor logs a warning to remind you.

Return a dict with at least `user_id`. It becomes the thread and memory owner, so take it from the verified credential, never from a client-set header or body field. An optional `roles` claim feeds the built-in role-based access, and a token `scope` or `scopes` claim can only narrow permissions. See [Authentication](/docs/server/auth).

### evals and tests

`evals/weather_agents_eval.py` defines `get_eval_config()` (it returns `EvalPresets.tool_usage(threshold=0.6)`) and `get_eval_set()` (an `EvalSetBuilder` set with a greeting case and `get_weather` tool tests). `evals/user_simulator_eval.py` defines `get_scenarios()` and runs simulated-user conversations. Run them with `10xgraph eval`.

The tests cover the agent configuration and routing (`test_graph_nodes.py`), the `get_weather` tool (`test_catalog_tools.py`) and the eval set and report writing (`test_agent_eval.py`). `conftest.py` only sets a dummy `GEMINI_API_KEY`, so the tests run offline. Run them with `10xgraph test`. See [Test and evaluate](/docs/get-started/tutorial/test-and-evaluate) and [Testing](/docs/testing).

### .env.example

The env template holds app, CORS, request-limit, security-header, Snowflake, Sentry and API key settings, plus `REDIS_URL` with a Redis cache store and `JWT_SECRET_KEY` with JWT auth. Copy it to `.env` and fill in your provider key. Every variable is in the [environment reference](/docs/reference/api-cli/environment).

### pyproject.toml, .python-version and pre-commit

`pyproject.toml` names the project after your agent, requires Python 3.12 or later, and depends on `10xgraph`, `10xgraph-api` and `google-genai`. A `test` extra adds `pytest`, `pytest-asyncio`, `pytest-cov` and `pytest-env`. It also configures ruff (line length 100, target `py312`) and pytest with coverage over `graph`.

`.python-version` pins `3.13`. If you run 3.12, edit it. `.pre-commit-config.yaml` runs the standard pre-commit hooks, pyupgrade, ruff format, ruff and bandit on commit. Install them with `pre-commit install`.

If you use a different model provider, swap `google-genai` for that provider's SDK and change `model` and `provider` in `agent.py`.

## Understand the generated 10xgraph.json

Init builds `10xgraph.json` from your answers and writes it after the template files, so the generated file contains only the keys below. With `--auth custom`, it looks like this.

```json title="10xgraph.json"
{
  "agent": "graph.agent:app",
  "env": ".env",
  "auth": {
    "method": "custom",
    "path": "auth.agent_auth:AgentAuth"
  },
  "thread_name_generator": "first_message",
  "ag_ui": {
    "enabled": false,
    "allow_client_tools": false
  },
  "websocket": {
    "enabled": false
  },
  "remote_tools": [],
  "injectq": "graph.agent:container",
  "cache_store": {
    "type": "memory",
    "rate_limit": {
      "enabled": true,
      "requests": 100,
      "window": 60,
      "by": "user",
      "trusted_proxy_headers": false,
      "fail_open": false,
      "exclude_paths": ["/ping", "/docs", "/redocs", "/openapi.json"]
    },
    "token_revocation": true
  },
  "audit": {
    "enabled": true,
    "sinks": ["log"],
    "include_reads": true
  },
  "test": {
    "path": "tests",
    "coverage": true,
    "coverage_threshold": 70
  },
  "evaluation": {
    "directory": "evals",
    "output_dir": "eval_reports",
    "threshold": 0.75,
    "parallel": false,
    "max_concurrency": 4,
    "timestamp_files": true
  }
}
```

| Key | Written when | Value from init |
|---|---|---|
| `agent` | Always | `graph.agent:app` |
| `env` | Always | `.env` |
| `auth` | Always | `null` for none, `{"method": "jwt"}` for JWT (needs `JWT_SECRET_KEY`; `JWT_ALGORITHM` defaults to `HS256`), or `{"method": "custom", "path": "auth.agent_auth:AgentAuth"}` |
| `ag_ui` | Always | `{"enabled": false}`, the AG-UI endpoint is off. Full adds `"allow_client_tools": false` |
| `thread_name_generator` | Always | unset for Quick, `first_message` for Full; `module:attr` for your own class |
| `injectq` | Full | `graph.agent:container`, defined in `graph/agent.py` |
| `cache_store` | Full | `{"type": "memory", ...}` with the default memory storage and with `sqlite`; `{"type": "redis", ...}` with `postgres`, `postgres-memory` or a worker, and then there is no `url`, so Redis comes from `REDIS_URL`. It holds `rate_limit` (100 requests per 60 seconds, by `user`, `fail_open` false) and `token_revocation` (`true` with auth). `--cache-store` overrides the choice (a worker refuses `memory`); `--no-rate-limit` and `--no-token-revocation` leave those two out |
| `websocket` | Always | `{"enabled": false}`, or `true` with `--websocket` |
| `remote_tools` | Full | `[]`, where frontend tools are declared |
| `audit` | Full | `{"enabled": true, "sinks": ["log"], "include_reads": true}`, JSON lines on stdout |
| `store` | Full with Postgres memory storage | `graph.agent:store` |
| `worker` | Full with a background worker | The broker type and url, and `"tasks": ["worker.tasks"]` |
| `test` | Full, unless tests are turned off | Path `tests`, coverage on, threshold 70 |
| `evaluation` | Full, unless evals are turned off | Directory `evals`, output `eval_reports`, threshold 0.75 |

There is no `checkpointer` key (it is refused at startup): the server uses the checkpointer you pass to `graph.compile(checkpointer=...)`. The Quick setup adds no `cache_store`. Run `10xgraph config` to change any of these. For every key and default, see the [configuration reference](/docs/reference/api-cli/configuration), for what is on by default see [Configure 10xgraph.json](/docs/server/configure#what-is-on-by-default), and for rate-limit options see [Rate limiting](/docs/server/rate-limiting).

## Fix these before you deploy

<Callout type="tip" title="Switch to a durable checkpointer">

The template uses `InMemoryCheckpointer`, so threads and state vanish when the server restarts. Choose a durable checkpointer before deploying: see [Set up checkpointing](/docs/guides/set-up-checkpointing) and [Checkpointing and threads](/docs/concepts/checkpointing-and-threads).

</Callout>

<Callout type="note" title="Tighten the env defaults">

`.env.example` ships placeholder values for `ORIGINS` and `ALLOWED_HOST`. Replace both with your real domains. With `MODE=production` the server refuses to start on a wildcard for either one, or on enabled docs paths. Leave `DOCS_PATH` and `REDOCS_PATH` empty to keep the API docs off. Never commit `.env`.

</Callout>
