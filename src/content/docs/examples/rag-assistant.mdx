This is a complete, deployable app: a documentation assistant for a fictional product called Lumen. A ReAct agent built with `ReactAgent` answers questions from a Qdrant knowledge base and cites the source file for each fact. A React chat UI streams the answer and shows the sources. The 10xGraph API server serves the graph, Postgres and Redis keep threads across restarts, and everything starts with `docker compose up`.

It uses three model providers on purpose. The chat agent runs `claude-sonnet-5-5` (Anthropic), the query rewriter runs `gemini-2.5-flash` (Google), and embeddings use `text-embedding-3-small` (OpenAI).

## What you will build

A documentation assistant for Lumen. You ask a question in a React chat UI. A ReAct agent rewrites the question into a search query, searches a Qdrant collection of documentation chunks, and answers with the source file named for each fact. The UI streams the answer and lists the cited sources taken from the tool results.

The stack runs with one `docker compose up`: the 10xGraph API server, an nginx-served frontend, Postgres and Redis for thread persistence, and Qdrant for vectors.

## Architecture

### Components

| Component | Technology | Role |
|---|---|---|
| Chat agent | `ReactAgent`, `claude-sonnet-5-5` (Anthropic) | Decides when to call tools, writes the grounded, cited answer |
| Query rewriter | `call_llm` with `gemini-2.5-flash` (Google) | Turns a chat question into a short keyword search query |
| Embeddings | `OpenAIEmbedding`, `text-embedding-3-small` (OpenAI) | Vectors for ingest and for every search |
| Retrieval | `QdrantStore`, collection `docs_kb` | Vector similarity search over doc chunks |
| API server | 10xGraph API server (`10xgraph-api`), gunicorn with uvicorn workers | Loads `graph.agent:app`, exposes `/v1/graph/stream`, threads and `/ping` |
| Thread storage | `PgCheckpointer`: Postgres 16 plus Redis 7 | Durable thread state (Postgres) and a fast cache (Redis) |
| Rate limiting | Redis backend, configured in `10xgraph.json` | 60 requests per 60 seconds per IP |
| Frontend | React 19, Vite 6, `10xgraph-client`, served by nginx | Chat, thread list, source display |
| Ingest job | `ingest.py` | Chunks `backend/data/*` and writes the chunks to Qdrant |

### Docker services

`docker-compose.yml` defines six services: `api`, `frontend`, `postgres`, `redis`, `qdrant`, and `ingest`. The `ingest` service sits behind a Compose profile, so it only runs when you ask for it.

### Request flow

```text
Browser (React, port 3000)
   |  POST /api/v1/graph/stream   (same origin)
   v
nginx (frontend container)         buffering off, strips nothing: /api/ -> http://api:8000/
   |
   v
10xGraph API server (api:8000)
   |  load thread state            PgCheckpointer: Redis cache -> Postgres
   v
ReactAgent  (claude-sonnet-5-5, Anthropic)
   |  1. tool call: query_rewriter(question)
   |        `--> call_llm("gemini-2.5-flash")  (Google)  -> short search query
   |  2. tool call: search_docs(query)
   |        `--> QdrantStore.asearch(KB_CONFIG, query)
   |                 `--> embed query with OpenAI text-embedding-3-small
   |                 `--> Qdrant docs_kb, owner = system_user_id("docs_kb")
   |                 `--> JSON: [source, title, score, content]
   |  3. final answer, streamed, names (source: file) for each fact
   v
SSE stream back through nginx to the browser
   |  assistant text chunks -> chat bubble
   |  tool messages         -> parsed into the "Sources" list
   v
PgCheckpointer saves the thread (background write) -> thread list and history

Offline: ingest.py -> chunk files in backend/data -> OpenAI embeddings -> Qdrant docs_kb
```

## Key concepts

- `ReactAgent`: prebuilt ReAct loop; wires the model node, tool node and routing.
- `PgCheckpointer`: stores thread state in Postgres with a Redis cache, so threads survive restarts.
- `QdrantStore` with `OpenAIEmbedding`: vector search over the knowledge base.
- `system_user_id("docs_kb")`: reserved owner for shared data such as a RAG knowledge base.
- `call_llm`: single-turn call used by the query rewriter; the provider is chosen from the model name.
- `10xgraph.json`: tells the API server which graph to load and configures rate limiting and auth.
- `TenxGraphClient` from `10xgraph-client`: `stream()`, `threads()`, `threadMessages()`, `deleteThread()`.
- `tenxgraph.qa.testing`: runs graph logic in tests with no LLM.

## How the code works

### Backend

#### `graph/store.py`: one shared Qdrant handle

```python
COLLECTION = "docs_kb"

# Shared documents are not owned by a person. They belong to a reserved system owner,
# so a user-scoped memory search can never return them (and vice versa).
KB_OWNER = system_user_id("docs_kb")

# Search and ingest must agree on both values, so both read them from here.
KB_CONFIG = {"user_id": KB_OWNER, "collection": COLLECTION}
```

Qdrant stores each chunk under an owner. A knowledge base belongs to no person, so it gets a reserved system owner from `system_user_id`. That keeps it apart from per-user memories. `KB_CONFIG` is the one place that holds the owner and collection, and both `ingest.py` and `search_docs` import it, so writes and reads can not drift apart.

```python
@lru_cache(maxsize=1)
def get_store() -> QdrantStore:
    """Qdrant over the network, with OpenAI embeddings (a third company from the chat model)."""
    return QdrantStore(
        embedding=OpenAIEmbedding(model="text-embedding-3-small"),
        host=os.getenv("QDRANT_HOST", "localhost"),
        port=int(os.getenv("QDRANT_PORT", "6333")),
        collection=COLLECTION,
    )
```

`get_store()` builds the store on first use and caches it. Importing the module in tests opens no connection and needs no key. The host and port come from the environment so the same code runs in Compose (`qdrant`) and on your laptop (`localhost`). The embedding model is set here; if you change it, re-ingest into a fresh collection because vector sizes must match.

#### `graph/tools.py`: the two tools

```python
async def query_rewriter(question: str) -> str:
    # A cheap, fast model from a different company than the chat model. call_llm picks
    # the Google client from the model name.
    text, *_ = await call_llm(
        "gemini-2.5-flash",
        question,
        system_prompt=REWRITER_PROMPT,
        max_tokens=64,
        temperature=0.0,
    )
    return text.strip() or question
```

Chat questions are often vague ("how much is it?"). The rewriter asks Gemini for a short keyword query with `temperature=0.0` so the result is stable. `call_llm` chooses the Google client from the model name. If the model returns an empty string, the tool falls back to the original question, so retrieval never runs on an empty query.

```python
async def search_docs(query: str, limit: int = 4) -> str:
    results = await get_store().asearch(KB_CONFIG, query, limit=limit)
    return json.dumps(format_hits(results))
```

`search_docs` runs the vector search as the knowledge-base owner and returns a JSON string. `format_hits` keeps only `source`, `title`, `score` and `content`, and rounds the score to three decimals. The same JSON serves two readers: the model uses `content` to answer, and the UI parses `source`, `title` and `score` to show citations. The `@tool` description tells the model to cite `source`.

#### `graph/agent.py`: the graph

```python
SYSTEM_PROMPT = [
    {
        "role": "system",
        "content": (
            "You are a documentation assistant for the Lumen product. "
            "For every question about the product: 1) call query_rewriter with the question, "
            "2) call search_docs with the rewritten query, 3) answer only from the returned "
            "passages and name the source file for each fact, for example (source: pricing.md). "
            "If the passages do not contain the answer, say you could not find it."
        ),
    }
]
```

The prompt fixes the tool order (rewrite, then search), forces answers to come from the returned passages, and asks for a `(source: file)` tag per fact. The last sentence gives the model a safe way out when retrieval finds nothing.

```python
checkpointer = PgCheckpointer(
    postgres_dsn=os.environ["POSTGRES_DSN"],
    redis_url=os.environ["REDIS_URL"],
)

react_agent = ReactAgent(
    model="claude-sonnet-5-5",
    system_prompt=SYSTEM_PROMPT,
    tools=[query_rewriter, search_docs],
    trim_context=True,
)

# `store` is registered so the server's graceful shutdown (compiled.aclose()) also
# releases the Qdrant client together with the checkpointer.
app = react_agent.compile(checkpointer=checkpointer, store=get_store())
```

`PgCheckpointer` writes thread state to Postgres and caches it in Redis. It reads both settings with `os.environ[...]`, so the app fails at import with a clear `KeyError` if one is missing. `ReactAgent` wires the model node, the tool node and the routing loop for you. `trim_context=True` trims long histories. Passing `store=` to `compile()` registers the Qdrant client, so `aclose()` on shutdown releases it together with Postgres and Redis. The module-level name `app` is what `10xgraph.json` points at.

#### `ingest.py`: building the knowledge base

```python
def chunk_text(text: str, max_chars: int = 1200) -> list[tuple[str, str]]:
    """Split on markdown headings. Returns (heading, body) pairs, long bodies cut by paragraph."""
    sections = re.split(r"(?m)^(?=#{1,3} )", text)
```

Each file is split at headings (levels 1 to 3). A section longer than 1,200 characters is cut at paragraph breaks. Splitting on structure keeps one idea per chunk, which makes retrieval sharper than fixed-size windows. Files without headings, like `security.txt`, become one chunk per section of text.

```python
            await store.astore(
                KB_CONFIG,
                body,
                category="docs",
                metadata={"source": path.name, "title": heading, "chunk": i},
                # A fixed id makes re-ingesting update the chunk instead of duplicating it.
                memory_id=str(uuid.uuid5(NAMESPACE, f"{path.name}:{i}")),
            )
```

Every chunk is stored with `source` and `title` metadata, which `search_docs` later returns for citations. The id is a `uuid5` of file name and chunk index, so re-running the job overwrites chunks instead of piling up duplicates.

#### `10xgraph.json`: server config

```json
  "agent": "graph.agent:app",
  "env": "../.env",
  "auth": null,
```

`agent` is the import path of the compiled graph. `env` names the dotenv file the server loads. `auth` is `null`, so any caller can use the API; see [Deploy to production](#deploy-to-production).

```json
    "enabled": true,
    "backend": "redis",
    "redis": {
      "url": "${REDIS_URL}",
      "prefix": "docs-assistant:rate-limit"
    },
    "requests": 60,
    "window": 60,
    "by": "ip",
    "fail_open": true,
```

Rate limiting is on, counted in Redis so all workers share one counter: 60 requests per 60 seconds per client IP. `fail_open` lets requests through if Redis is down. Health and doc paths are excluded through `exclude_paths`. The `test` block tells `10xgraph test` where the tests live.

#### Tests

`tests/test_rag.py` covers the pieces that do not need a network. `FakeStore` replaces Qdrant and records the config it was called with, so the first test checks both the JSON shape and that the search used `KB_OWNER`. The second test patches `call_llm` to confirm the rewriter uses `gemini-2.5-flash` and falls back to the question on an empty reply. The third checks heading-based chunking. The fourth runs the graph with `QuickTest.single_turn`, which scripts the model reply.

### Frontend

#### `client.ts` and the proxy

```ts
export const client = new TenxGraphClient({
  baseUrl: `${window.location.origin}/api`,
});
```

The browser only talks to its own origin under `/api`. In Docker, nginx forwards that prefix to the API. In dev, Vite does (`vite.config.ts` rewrites `/api` away and targets `API_URL`, default `http://localhost:8000`). One origin means no CORS setup. With JWT auth, pass `authToken` here.

#### `useChat.ts`: streaming and sources

```ts
        const stream = client.stream([Message.text_message(text, 'user')], {
          config: { thread_id: threadId },
          response_granularity: 'low',
        });
```

The `thread_id` in `config` ties the run to a saved thread. `response_granularity: 'low'` asks for messages only. A new random id creates a new thread on the server.

```ts
          if (msg.role === 'tool') {
            const found = blocks.filter((b) => b.type === 'tool_result').flatMap((b) => parseSources(b.output));
            if (found.length) patch((m) => ({ ...m, sources: [...m.sources, ...found] }));
          } else if (msg.role === 'assistant') {
            const t = blocks.filter((b) => b.type === 'text').map((b) => b.text).join('');
            if (!t) continue;
            // Deltas append. The final non-delta message carries the full text of that turn.
            patch((m) => ({ ...m, text: msg.delta ? m.text + t : t }));
          }
```

Two kinds of messages matter. Tool messages carry the `search_docs` JSON, which `parseSources` turns into citations. Assistant messages carry text: delta chunks are appended, and the final non-delta message replaces the text with the full turn. The `load` function replays saved history through the same parsing, attaching pending tool results to the next assistant message.

#### `App.tsx`, `ThreadList.tsx`, `ChatView.tsx`, `Sources.tsx`

```tsx
      const res = await client.threads({ limit: 50 });
      setThreads(res.data.threads.map((t) => ({ id: t.thread_id, name: t.thread_name || t.thread_id.slice(0, 8) })));
```

`App` owns the thread list and the active thread id, which starts as a new UUID. `ChatView` is keyed by the active id, so switching threads remounts it and reloads history. After each send, `onFinished` refreshes the list because the thread now exists on the server. `ThreadList` is a plain sidebar with select, new and delete. `Sources` groups hits by file name so each cited document appears once, with its section title and score.

#### Build files

`package.json` depends on `10xgraph-client`, React 19 and Vite 6. `npm run build` type-checks with `tsc --noEmit` and then builds. No component library is used; `styles.css` is plain CSS.

### Deployment

#### `backend/Dockerfile`

```dockerfile
CMD ["gunicorn", "-k", "uvicorn_worker.UvicornWorker", "-b", "0.0.0.0:8000", "--graceful-timeout", "600", "--timeout", "660", "tenxgraph_api.src.app.main:app"]
```

The image has two stages. The builder installs `requirements.txt` into a virtualenv, adds gunicorn and uvicorn-worker, and strips CLI-only assets. The runtime stage copies only the virtualenv and your code, runs as non-root uid 10001, defaults to `MODE=production` and `WEB_CONCURRENCY=2`, and has a Python-based health check on `/ping`. Gunicorn's graceful timeout is 600 seconds so a long agent run is not cut off during a deploy.

#### `docker-compose.yml`

```yaml
  api:
    build: ./backend
    environment:
      <<: *api-env
      # The image defaults to MODE=production, which refuses wildcard CORS origins and
      # hosts. The browser only talks to nginx (same origin), so development mode keeps
      # this demo to one command. See the README for the production settings.
      MODE: development
    # Matches the --graceful-timeout in the image: on SIGTERM the server stops accepting
    # runs and lets in-flight ones finish before closing Postgres, Redis and Qdrant.
    stop_grace_period: 600s
```

A shared `x-api-env` block feeds the same variables to `api` and `ingest`. The `${VAR:?set it in .env}` form makes Compose stop with a message if a key is missing. `api` waits for healthy Postgres and Redis. `frontend` waits for a healthy `api`. Ports for `api`, `frontend` and `qdrant` bind to `127.0.0.1` only. `pgdata` and `qdrantdata` volumes keep data across restarts.

#### `frontend/nginx.conf`

```nginx
  location /api/ {
    proxy_pass http://api:8000/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_buffering off;
    proxy_read_timeout 600s;
  }
```

`proxy_buffering off` is what lets streamed tokens reach the browser as they arrive. The 600 second read timeout matches the long-run allowance in the API image. Everything else falls back to `index.html`.

"""Tools the docs assistant can call: a Gemini query rewriter and a Qdrant search."""

from __future__ import annotations

import json
from typing import Any

from graph.store import KB_CONFIG, get_store
from tenxgraph.core.llm import call_llm
from tenxgraph.utils import tool


REWRITER_PROMPT = (
    "Rewrite the user's question as a short keyword-style search query for a product "
    "documentation index. Resolve pronouns, drop filler words, keep product names and "
    "numbers. Reply with the query only."
)


@tool(
    name="query_rewriter",
    description=(
        "Rewrite a user question into a concise search query. Call this first, then pass "
        "its result to search_docs."
    ),
    tags=["rag"],
)
async def query_rewriter(question: str) -> str:
    # A cheap, fast model from a different company than the chat model. call_llm picks
    # the Google client from the model name.
    text, *_ = await call_llm(
        "gemini-2.5-flash",
        question,
        system_prompt=REWRITER_PROMPT,
        max_tokens=64,
        temperature=0.0,
    )
    return text.strip() or question


def format_hits(results: list[Any]) -> list[dict[str, Any]]:
    """Reduce store results to what the model and the UI need. The UI reads `source`."""
    return [
        {
            "source": r.metadata.get("source", "unknown"),
            "title": r.metadata.get("title", ""),
            "score": round(float(r.score), 3),
            "content": r.content,
        }
        for r in results
    ]


@tool(
    name="search_docs",
    description=(
        "Search the product documentation. Returns a JSON list of passages with `source` "
        "(file name), `title`, `score` and `content`. Cite the `source` in your answer."
    ),
    tags=["rag"],
)
async def search_docs(query: str, limit: int = 4) -> str:
    results = await get_store().asearch(KB_CONFIG, query, limit=limit)
    return json.dumps(format_hits(results))
```

"""Load the markdown/txt files in data/ into Qdrant as the shared knowledge base.

Splits each file into sections at markdown headings, embeds them with OpenAI and
stores them under the knowledge-base owner. Safe to re-run: chunk ids are stable.

Run: python ingest.py            (needs OPENAI_API_KEY and a reachable Qdrant)
"""

from __future__ import annotations

import asyncio
import re
import uuid
from pathlib import Path

from dotenv import load_dotenv
from graph.store import KB_CONFIG, get_store


DATA_DIR = Path(__file__).parent / "data"
NAMESPACE = uuid.UUID("6f1d2c1e-0b8e-4b53-9a52-3c1a7a0e5d11")


def chunk_text(text: str, max_chars: int = 1200) -> list[tuple[str, str]]:
    """Split on markdown headings. Returns (heading, body) pairs, long bodies cut by paragraph."""
    sections = re.split(r"(?m)^(?=#{1,3} )", text)
    chunks: list[tuple[str, str]] = []
    for section in filter(str.strip, sections):
        first, _, _ = section.partition("\n")
        heading = first.lstrip("# ").strip() if first.startswith("#") else ""
        body = section.strip()
        if len(body) <= max_chars:
            chunks.append((heading, body))
            continue
        current = ""
        for para in re.split(r"\n\s*\n", body):
            if current and len(current) + len(para) > max_chars:
                chunks.append((heading, current.strip()))
                current = ""
            current += para + "\n\n"
        if current.strip():
            chunks.append((heading, current.strip()))
    return chunks


async def main() -> None:
    load_dotenv()
    store = get_store()
    await store.asetup()

    total = 0
    for path in sorted(DATA_DIR.iterdir()):
        if path.suffix not in {".md", ".txt"}:
            continue
        for i, (heading, body) in enumerate(chunk_text(path.read_text(encoding="utf-8"))):
            await store.astore(
                KB_CONFIG,
                body,
                category="docs",
                metadata={"source": path.name, "title": heading, "chunk": i},
                # A fixed id makes re-ingesting update the chunk instead of duplicating it.
                memory_id=str(uuid.uuid5(NAMESPACE, f"{path.name}:{i}")),
            )
            total += 1
        print(f"ingested {path.name}")
    print(f"done: {total} chunks")
    await store.arelease()


if __name__ == "__main__":
    asyncio.run(main())

import { useCallback, useRef, useState } from 'react';
import { Message, StreamEventType } from '10xgraph-client';
import { client } from './client';
import type { ChatMessage, Source } from './types';

// The search_docs tool returns a JSON string: [{ source, title, score, content }].
function parseSources(output: unknown): Source[] {
  try {
    const data = typeof output === 'string' ? JSON.parse(output) : output;
    return Array.isArray(data) ? (data as Source[]).filter((s) => s && s.source) : [];
  } catch {
    return [];
  }
}

export function useChat(threadId: string) {
  const [messages, setMessages] = useState<ChatMessage[]>([]);
  const [busy, setBusy] = useState(false);
  const [error, setError] = useState<string | null>(null);
  const abort = useRef(false);

  // Load the saved history of an existing thread (tool results carry the sources).
  const load = useCallback(async () => {
    setMessages([]);
    setError(null);
    try {
      const res = await client.threadMessages({ threadId });
      const out: ChatMessage[] = [];
      let pending: Source[] = [];
      for (const m of res.data.messages) {
        const blocks = (m.content ?? []) as any[];
        if (m.role === 'tool') {
          for (const b of blocks) if (b.type === 'tool_result') pending.push(...parseSources(b.output));
        } else if (m.role === 'user' || m.role === 'assistant') {
          const text = blocks.filter((b) => b.type === 'text').map((b) => b.text).join('');
          if (!text) continue;
          out.push({ id: m.message_id ?? crypto.randomUUID(), role: m.role, text, sources: m.role === 'assistant' ? pending : [] });
          if (m.role === 'assistant') pending = [];
        }
      }
      setMessages(out);
    } catch {
      // A brand new thread has no history yet.
    }
  }, [threadId]);

  const send = useCallback(
    async (text: string) => {
      setError(null);
      setBusy(true);
      abort.current = false;
      const assistantId = crypto.randomUUID();
      setMessages((prev) => [
        ...prev,
        { id: crypto.randomUUID(), role: 'user', text, sources: [] },
        { id: assistantId, role: 'assistant', text: '', sources: [] },
      ]);
      const patch = (fn: (m: ChatMessage) => ChatMessage) =>
        setMessages((prev) => prev.map((m) => (m.id === assistantId ? fn(m) : m)));

      try {
        const stream = client.stream([Message.text_message(text, 'user')], {
          config: { thread_id: threadId },
          response_granularity: 'low',
        });
        for await (const chunk of stream) {
          if (abort.current) break;
          if (chunk.event === StreamEventType.ERROR) {
            setError(String(chunk.data?.message ?? 'The run failed'));
            continue;
          }
          const msg = chunk.message;
          if (chunk.event !== StreamEventType.MESSAGE || !msg) continue;
          const blocks = (msg.content ?? []) as any[];

          if (msg.role === 'tool') {
            const found = blocks.filter((b) => b.type === 'tool_result').flatMap((b) => parseSources(b.output));
            if (found.length) patch((m) => ({ ...m, sources: [...m.sources, ...found] }));
          } else if (msg.role === 'assistant') {
            const t = blocks.filter((b) => b.type === 'text').map((b) => b.text).join('');
            if (!t) continue;
            // Deltas append. The final non-delta message carries the full text of that turn.
            patch((m) => ({ ...m, text: msg.delta ? m.text + t : t }));
          }
        }
      } catch (e) {
        setError(e instanceof Error ? e.message : String(e));
      } finally {
        setBusy(false);
      }
    },
    [threadId],
  );

  return { messages, busy, error, send, load };
}
```

# Backend image for the docs assistant. Same layout `10xgraph build` generates:
# two stages, non-root user, gunicorn with uvicorn workers, long graceful drain on SIGTERM.

# ---- Stage 1: install dependencies into a virtualenv ----
# For reproducible production builds, pin both FROM lines by digest
# (python:3.13-slim@sha256:...) and install from a hash-locked
# requirements file (pip install --require-hashes -r requirements.txt).
FROM python:3.13-slim AS builder

ENV PIP_NO_CACHE_DIR=1
ENV PIP_DISABLE_PIP_VERSION_CHECK=1
WORKDIR /build
RUN python -m venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"

# Every 10xGraph dependency ships prebuilt wheels, so no compiler is needed. If one
# of your own dependencies has to build from source, uncomment this. It only lives
# in the builder stage and never reaches the final image.
# RUN apt-get update \
#     && apt-get install -y --no-install-recommends build-essential \
#     && rm -rf /var/lib/apt/lists/*

# Install exactly the dependencies listed in your requirements file
COPY requirements.txt requirements.txt
RUN pip install -r requirements.txt

# Production process manager: gunicorn supervising uvicorn workers. These are
# not dependencies of 10xgraph-api, so the image installs them here.
RUN pip install "gunicorn>=23,<27" "uvicorn-worker>=0.4,<1"

# Strip CLI-only assets the server never loads: project scaffolds, the bundled
# agent skill, and the local config editor (HTML/JS). Only the server code and
# its dependencies stay in the image.
RUN python -I -c "import importlib.util, pathlib, shutil; spec = importlib.util.find_spec('tenxgraph_api'); cli = pathlib.Path(spec.origin).parent / 'cli' if spec and spec.origin else None; [shutil.rmtree(cli / d, ignore_errors=True) for d in ('templates', 'config_editor') if cli]"

# Remove the CLI's own libraries (typer, rich, questionary and what only they pull
# in). A package that one of your dependencies still needs is kept.
RUN python -I -c "import importlib.util, runpy; importlib.util.find_spec('tenxgraph_api._slim_image') and runpy.run_module('tenxgraph_api._slim_image', run_name='__main__')"

# The server never runs pip, so drop it from the virtualenv the runtime copies
# (about 13 MB). The base image keeps its own pip for debugging.
RUN pip uninstall -y pip

# ---- Stage 2: runtime image ----
FROM python:3.13-slim

# Set environment variables
ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1
ENV PYTHONPATH=/app
ENV PATH="/opt/venv/bin:$PATH"
# Default to production; overridable via .env or runtime env.
# In production the local in-memory telemetry store stays disabled
# (use OTEL / a publisher for observability instead).
ENV MODE=production
ENV IS_DEBUG=false
# Gunicorn worker count. Gunicorn reads WEB_CONCURRENCY natively; a sane default
# here beats gunicorn's built-in default of 1 worker. Tune to your CPU/memory
# at deploy time, e.g. `docker run -e WEB_CONCURRENCY=8 ...`.
ENV WEB_CONCURRENCY=2

# Create a non-root user with a fixed uid that owns the work directory.
# uploads/ exists up front so a volume mounted there inherits that owner.
RUN groupadd -r -g 10001 appuser \
    && useradd -r -u 10001 -g appuser -d /app -s /usr/sbin/nologin appuser \
    && mkdir -p /app/uploads && chown appuser:appuser /app /app/uploads
WORKDIR /app

# Only the installed virtualenv comes over from the builder
COPY --from=builder /opt/venv /opt/venv

# Copy application code. --chown sets ownership while copying; a separate
# `chown -R` afterwards would write a second copy of every file into a new layer.
COPY --chown=appuser:appuser . .
# Numeric, so Kubernetes runAsNonRoot can verify it
USER 10001:10001

# Expose port
EXPOSE 8000

# Health check (Python stdlib, so the image needs no curl)
HEALTHCHECK --interval=30s --timeout=30s --start-period=5s --retries=3 \
    CMD python -c "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/ping', timeout=5)" || exit 1

# Run the application (production)
# Use Gunicorn with Uvicorn workers for better performance and multi-core
# utilization
#
# --graceful-timeout is critical: an agent run can legitimately take
# minutes (the LLM client alone allows up to 600s). Gunicorn's default
# graceful timeout is 30s, so on every rolling deploy SIGTERM would
# hard-kill runs that were still mid-flight, truncating them. Give
# in-flight runs time to finish draining instead.
CMD ["gunicorn", "-k", "uvicorn_worker.UvicornWorker", "-b", "0.0.0.0:8000", "--graceful-timeout", "600", "--timeout", "660", "tenxgraph_api.src.app.main:app"]

## Deploy to production

The demo is set up for one command, not for the open internet. These are the changes the shipped config supports.

- **Auth.** `10xgraph.json` ships with `"auth": null`. For production set `"auth": "jwt"`, set `JWT_SECRET_KEY` and `JWT_ALGORITHM`, and pass `authToken` to `TenxGraphClient` in `frontend/src/client.ts`. Thread ownership is then enforced per user. Use `"auth": {"method": "custom", "path": "module:Class"}` for your own identity provider.
- **Mode and CORS.** Compose sets `MODE: development`. The image itself defaults to `MODE=production`, which refuses wildcard `ORIGINS` and `ALLOWED_HOST`. Remove the `MODE` override and set both to your real domain.
- **Redis rate limiting.** Already enabled with the Redis backend, 60 requests per 60 seconds per IP. Switch `"by"` to `"user"` once auth is on, and set `trusted_proxy_headers` when running behind a load balancer.
- **Postgres and Redis.** Compose runs both with a demo password (`docs`). Replace the password, point `POSTGRES_DSN` and `REDIS_URL` at managed instances if you have them, and do not publish the Postgres, Redis or Qdrant ports.
- **Graceful shutdown.** The server drains in-flight runs on SIGTERM, then calls `aclose()` on the compiled graph. Keep your orchestrator's grace period at least 600 seconds (`stop_grace_period` here, `terminationGracePeriodSeconds` on Kubernetes).
- **Workers.** Tune `WEB_CONCURRENCY` (default 2) to your CPU and memory.
- **Secrets.** `.env` is excluded from the backend image by `.dockerignore`. Inject keys through your platform's secret store.
- **Images.** The backend Dockerfile comments describe pinning base images by digest and installing from a hash-locked requirements file for reproducible builds.

## Customize it

- **Your own docs.** Replace the files in `backend/data/` with `.md` or `.txt` files and run `docker compose run --rm ingest`. Update the product name in `SYSTEM_PROMPT`.
- **A different chat model.** Change the model string in `graph/agent.py` and install the matching extra. `model="gpt-5-mini"` needs the `openai` extra; `model="gemini-2.5-flash"` needs `google-genai`. No `provider=` argument is needed.
- **A different rewriter or embedding model.** The rewriter model is a string in `graph/tools.py`. The embedding model is in `graph/store.py`; re-ingest into a fresh collection after changing it.
- **More passages.** `search_docs` takes `limit` (default 4).
- **Different chunking.** Edit `chunk_text` in `ingest.py`, then re-ingest.
- **Another UI.** The frontend uses only `stream`, `threads`, `threadMessages` and `deleteThread`. Any client that speaks the same API can replace it.
