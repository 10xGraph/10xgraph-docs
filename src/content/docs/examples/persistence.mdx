A checkpointer saves an agent's conversation so it can continue by `thread_id`, even after the process restarts. This example runs the same weather agent against three checkpointers: in-memory, SQLite and PostgreSQL with Redis. The agent uses DeepSeek `deepseek-chat` through its OpenAI-compatible endpoint.

## What you will build

The same small weather agent, run against three checkpointers. Each script chats on a fixed `thread_id`, so a conversation continues where it left off. With SQLite and PostgreSQL you run the script twice, in two separate processes: the first run tells the agent your name and city, and the second run asks it to recall them. After each chat the script lists threads and reads the saved state and messages back.

## Key concepts

- `InMemoryCheckpointer()`: the default. Keeps state in the process, so nothing survives a restart.
- `SqliteCheckpointer(db_path)`: one SQLite file for state, messages and threads. Defaults to `~/.10xgraph/checkpointer.db` when `db_path` is omitted.
- `PgCheckpointer(postgres_dsn=..., redis_url=...)`: PostgreSQL for durable storage plus Redis for the hot cache. Other arguments are `pg_pool`, `redis`, `schema`, `pool_config` and `redis_pool_config`.
- `graph.compile(checkpointer=...)`: attaches the checkpointer to the graph.
- `thread_id` and `user_id` in the run config: `thread_id` selects the conversation, `user_id` scopes thread ownership.
- Read methods: `aget_state(config)`, `alist_messages(config, search=, offset=, limit=)`, `alist_threads(config, search=, offset=, limit=)`, `aget_thread(config)`.
- `aput_thread(config, ThreadInfo(...))`: optionally registers thread metadata such as a name.
- `await graph.aclose()`: flushes pending writes and releases connections.

```bash
python examples/persistence/in_memory.py

```

Delete `conversations.db` (created in the working directory) to start over with SQLite. For Postgres, use `docker compose ... down -v`.

## How the code works

### Choosing a checkpointer

Only one line differs between the three scripts.

```python
    checkpointer = InMemoryCheckpointer()
```

```python
    checkpointer = SqliteCheckpointer("conversations.db")
```

```python
    checkpointer = PgCheckpointer(
        postgres_dsn=os.getenv("POSTGRES_DSN", "postgresql://tenx:tenx@localhost:5432/tenx"),
        redis_url=os.getenv("REDIS_URL", "redis://localhost:6379/0"),
    )
    await checkpointer.asetup()  # creates the tables on first use; safe to repeat
```

`PgCheckpointer` enforces user isolation by default, so reads with a different `user_id` do not see the thread. Pass `enforce_user_isolation=False` for a single-tenant app.

### The agent and thread

```python
    agent = ReactAgent(
        model="deepseek-chat",  # DeepSeek through its OpenAI-compatible endpoint
        base_url="https://api.deepseek.com",
        api_key=os.environ["DEEPSEEK_API_KEY"],
        system_prompt=[{"role": "system", "content": "You are a friendly assistant."}],
        tools=[get_weather],
    )
    graph = agent.compile(checkpointer=checkpointer)
    # thread_id picks the conversation. user_id scopes ownership of the thread.
    config = {"thread_id": "customer-42", "user_id": "demo-user"}
```

`base_url` and `api_key` point the OpenAI client at DeepSeek. `compile(checkpointer=...)` attaches storage. The config is the same on every run, which is what makes the conversation continue.

### Same thread, separate runs (`sqlite.py`, `postgres.py`)

```python
    saved = await checkpointer.alist_messages(config)
    print(f"Restored {len(saved)} message(s) for this thread.\n")
    if not saved:
        await chat(graph, "Hi, my name is Sam and I live in Lisbon.", config)
    else:
        await chat(graph, "What is my name, and what is the weather where I live?", config)
```

On the second process, the checkpointer returns the earlier messages before the agent runs, and the agent answers from them. `in_memory.py` cannot cross processes, so it makes both calls in one process on the same thread to show the same behaviour:

```python
    await chat(graph, "Hi, my name is Sam and I live in Lisbon.", config)
    print("--- second run, same thread_id ---")
    await chat(graph, "What is my name, and what is the weather where I live?", config)
```

### Thread metadata

```python
    if await checkpointer.aget_thread(config) is None:
        info = ThreadInfo(
            thread_id=config["thread_id"], thread_name="Customer 42 chat", user_id=config["user_id"]
        )
        await checkpointer.aput_thread(config, info)
```

The graph writes state and messages itself. Thread metadata is separate: the scripts register a `ThreadInfo` so `alist_threads` has something to list. It is optional.

### Reading back

```python
    state = await checkpointer.aget_state(config)
    print(f"\nstate: {len(state.context)} messages, step {state.execution_meta.step}")

    messages = await checkpointer.alist_messages(config)
    for m in messages:
        print(f"  [{m.role}] {m.text()[:70]}")

    threads = await checkpointer.alist_threads(config)
    print("threads:", [(t.thread_id, t.thread_name) for t in threads])
```

`aget_state` returns the full `AgentState`, `alist_messages` returns stored messages with paging, and `alist_threads` returns `ThreadInfo` records. `in_memory.py` prints `state.context` instead of `alist_messages`, because the in-memory checkpointer can return the messages of a finished run twice.

### Closing

```python
    await graph.aclose()
```

This waits for background checkpoint writes and then releases the checkpointer's connections. See [graceful shutdown](/docs/examples/graceful-shutdown).

### `docker-compose.yml`

It starts `postgres:16` with user, password and database all set to `tenx`, and `redis:7`, both with health checks. These match the default DSN and Redis URL in `postgres.py`. The `pgdata` volume keeps data between restarts.

```python
"""Persist conversation state in process memory with InMemoryCheckpointer.

Two calls on the same thread_id: the second remembers the first, but nothing survives
a restart. Then it lists threads and reads state and messages back.
Run: python examples/persistence/in_memory.py
"""

import asyncio
import os

from dotenv import load_dotenv

from tenxgraph.core.state import Message
from tenxgraph.prebuilt.agent import ReactAgent
from tenxgraph.storage.checkpointer import InMemoryCheckpointer
from tenxgraph.utils import ThreadInfo


load_dotenv()


def get_weather(city: str) -> str:
    """Get the current weather for a city."""
    return f"It is 21 C and sunny in {city}."


async def chat(graph, text: str, config: dict) -> None:
    result = await graph.ainvoke({"messages": [Message.text_message(text)]}, config)
    print("user:     ", text)
    print("assistant:", result["messages"][-1].text())


async def main() -> None:
    # The default checkpointer. Good for tests and demos; nothing survives a restart.
    checkpointer = InMemoryCheckpointer()

    agent = ReactAgent(
        model="deepseek-chat",  # DeepSeek through its OpenAI-compatible endpoint
        base_url="https://api.deepseek.com",
        api_key=os.environ["DEEPSEEK_API_KEY"],
        system_prompt=[{"role": "system", "content": "You are a friendly assistant."}],
        tools=[get_weather],
    )
    graph = agent.compile(checkpointer=checkpointer)
    # thread_id picks the conversation. user_id scopes ownership of the thread.
    config = {"thread_id": "customer-42", "user_id": "demo-user"}

    # An in-memory checkpointer lives as long as this process. Two separate runs are
    # simulated with two calls on the same thread_id and the same checkpointer object.
    await chat(graph, "Hi, my name is Sam and I live in Lisbon.", config)
    print("--- second run, same thread_id ---")
    await chat(graph, "What is my name, and what is the weather where I live?", config)

    # The graph saves state and messages by itself. Thread metadata, such as a display
    # name for a thread list, is registered explicitly. It is optional.
    if await checkpointer.aget_thread(config) is None:
        info = ThreadInfo(
            thread_id=config["thread_id"], thread_name="Customer 42 chat", user_id=config["user_id"]
        )
        await checkpointer.aput_thread(config, info)

    # Read what was stored. All of these take the same config dict.
    state = await checkpointer.aget_state(config)
    print(f"\nstate: {len(state.context)} messages, step {state.execution_meta.step}")

    # state.context is the conversation the agent will see on the next turn.
    for m in state.context:
        print(f"  [{m.role}] {m.text()[:70]}")

    threads = await checkpointer.alist_threads(config)
    print("threads:", [(t.thread_id, t.thread_name) for t in threads])
    info = await checkpointer.aget_thread(config)
    print("thread info:", info.thread_id if info else None)

    # Flushes background checkpoint writes and releases the connections.
    await graph.aclose()


if __name__ == "__main__":
    asyncio.run(main())
```

## Using a different model

Change `model`, and remove `base_url` and `api_key`. For example `model="gpt-5-mini"` with `pip install "10xgraph[openai]"` and `OPENAI_API_KEY`, or `model="claude-sonnet-5-5"` with `pip install "10xgraph[anthropic]"` and `ANTHROPIC_API_KEY`.
